# Muse 正式数据导入操作手册

> 本文档提供当前版本可直接复制执行的正式数据导入步骤，覆盖 Railway Shell 与本地 PowerShell 两种运行方式。目标是将已经位于 Cloudflare R2 中的图片对象批量同步到 PostgreSQL 的 `images` 表中。

---

## 一、适用场景

你已经满足以下条件：

1. 正式图片已经全部上传到 Cloudflare R2
2. R2 图片可以通过 `R2_PUBLIC_URL` 对外访问
3. 生产数据库已经初始化了当前版本表结构
4. 后端代码已经包含 [backend/sync_r2_to_db.py](E:/MuseProject/backend/sync_r2_to_db.py)

你的目标是：

**把 R2 中已有图片对象批量写入数据库，让系统立即进入正式打分使用状态。**

---

## 二、正式导入前建议

### 2.1 如果是首次正式投产

建议先清掉旧测试任务和测试分数：

```sql
BEGIN;

DELETE FROM scores;
DELETE FROM annotation_tasks;

UPDATE images
SET
    score_count = 0,
    status = CASE
        WHEN COALESCE(deleted, FALSE) = TRUE THEN 'disabled'
        ELSE 'pending'
    END;

COMMIT;
```

### 2.2 如果要保留旧分数，只重新同步 R2 对象

只清任务即可：

```sql
DELETE FROM annotation_tasks;
```

## 三、需要的环境变量

当前脚本依赖以下变量：

| 变量名 | 是否必需 | 说明 |
|--------|----------|------|
| `DATABASE_URL` | 是 | PostgreSQL 连接串 |
| `R2_ACCOUNT_ID` | 是 | Cloudflare R2 Account ID |
| `R2_ACCESS_KEY_ID` | 是 | R2 Access Key |
| `R2_SECRET_ACCESS_KEY` | 是 | R2 Secret Key |
| `R2_BUCKET` | 是 | R2 Bucket 名称 |
| `R2_PUBLIC_URL` | 是 | 图片公网访问域名 |
| `R2_SYNC_PREFIX` | 否 | 仅同步某个前缀目录 |
| `R2_SYNC_BATCH_SIZE` | 否 | 每批写库数量，默认 `1000` |

## 四、你当前项目的现有值

根据你当前线上环境配置，你需要准备以下同类信息：

```env
R2_ACCOUNT_ID=<your-r2-account-id>
R2_ACCESS_KEY_ID=<your-r2-access-key-id>
R2_SECRET_ACCESS_KEY=<your-r2-secret-access-key>
R2_BUCKET=muse-images
R2_PUBLIC_URL=https://<your-r2-public-domain>
DATABASE_URL=postgresql+asyncpg://<user>:<password>@<host>/<database>?ssl=require
```

> 建议优先使用你线上部署平台中实际生效的环境变量值。如果文档中的值与线上配置不一致，以线上配置为准。

## 五、方案 A：在 Railway Shell 中直接执行

这是**最推荐**的方案，因为：

1. 不需要把生产数据库连接串复制到本地
2. 不需要重新配置一遍环境变量
3. 线上环境里通常已经具备这些变量

### 5.1 打开 Railway Shell

在 Railway 项目中打开后端服务的 Shell。

### 5.2 进入项目目录

根据你的镜像结构，先尝试：

```bash
cd /app/backend
```

如果不存在，再在 `/app` 下确认实际目录位置。

### 5.3 全量同步整个 R2 bucket

```bash
python sync_r2_to_db.py
```

### 5.4 只同步某个前缀目录

例如只同步 `dataset/final/`：

```bash
export R2_SYNC_PREFIX="dataset/final/"
python sync_r2_to_db.py
```

### 5.5 调整批量写入大小

例如每批 2000 条：

```bash
export R2_SYNC_BATCH_SIZE="2000"
python sync_r2_to_db.py
```

### 5.6 线上执行完成后检查

```sql
SELECT COUNT(*) FROM images;
```

```sql
SELECT id, object_key, public_url, status, score_count
FROM images
ORDER BY id DESC
LIMIT 20;
```

```sql
SELECT status, COUNT(*)
FROM images
GROUP BY status
ORDER BY status;
```

## 六、方案 B：在本地 PowerShell 中执行

如果你更希望在本地执行，同样可行。

### 6.1 打开 PowerShell

进入项目后端目录：

```powershell
cd E:\MuseProject\backend
```

### 6.2 配置环境变量

下面这份可以直接复制执行：

```powershell
$env:DATABASE_URL="postgresql+asyncpg://<user>:<password>@<host>/<database>?ssl=require"
$env:R2_ACCOUNT_ID="<your-r2-account-id>"
$env:R2_ACCESS_KEY_ID="<your-r2-access-key-id>"
$env:R2_SECRET_ACCESS_KEY="<your-r2-secret-access-key>"
$env:R2_BUCKET="muse-images"
$env:R2_PUBLIC_URL="https://<your-r2-public-domain>"
$env:R2_SYNC_PREFIX=""
$env:R2_SYNC_BATCH_SIZE="1000"
```

### 6.3 执行脚本

```powershell
python .\sync_r2_to_db.py
```

### 6.4 如果只同步某个目录前缀

```powershell
$env:R2_SYNC_PREFIX="dataset/final/"
python .\sync_r2_to_db.py
```

### 6.5 如果想提高批量写入大小

```powershell
$env:R2_SYNC_BATCH_SIZE="2000"
python .\sync_r2_to_db.py
```

## 八、成功判定标准

只要满足以下条件，就说明导入成功：

1. `images` 表数量与你 R2 中图片对象数量大体一致
2. 新写入的记录 `public_url` 可直接访问图片
3. `status` 大部分为 `pending`
4. 用户点击“开始打分”后能正常拿到图片任务

建议执行：

```sql
SELECT COUNT(*) FROM images;
```

```sql
SELECT COUNT(*) FROM images WHERE status = 'pending';
```

```sql
SELECT COUNT(*) FROM images WHERE public_url IS NULL;
```

最后一条正常结果应该尽量为 `0`。

## 九、正式投入使用前的最后检查

### 9.1 抽查 3 张图

```sql
SELECT id, object_key, public_url
FROM images
WHERE status = 'pending'
LIMIT 3;
```

把 `public_url` 复制到浏览器中直接打开，确认图片能显示。

### 9.2 测一轮真实打分

用普通账号：

1. 登录
2. 点击开始
3. 打 1 张分
4. 确认 `scores` 表已经有记录

检查 SQL：

```sql
SELECT id, image_id, user_id, aesthetic_score, completeness_score, submitted_at
FROM scores
ORDER BY id DESC
LIMIT 10;
```

## 十、常见问题

### 10.1 为什么脚本跑了但图片数量不对？

先检查：

1. `R2_SYNC_PREFIX` 是否误填
2. R2 中是否有非图片对象
3. 图片后缀是否超出当前支持范围

当前支持：
- `.webp`
- `.jpg`
- `.jpeg`
- `.png`

### 10.2 为什么系统说没有可分配图片？

检查：

```sql
SELECT status, COUNT(*)
FROM images
GROUP BY status
ORDER BY status;
```

如果 `pending = 0`，要么图片状态不对，要么图片都已打分，要么被 `disabled` 了。

### 10.3 10 万张会不会太慢？

可以跑，属于正常初始化任务。  
当前脚本已是批量写库版本，适合 10 万张规模。

---

## 十一、推荐执行结论

对于你的正式投产场景，推荐顺序是：

1. 清空旧测试任务
2. 在 Railway Shell 中运行 `sync_r2_to_db.py`
3. 检查 `images` 表数量和状态
4. 抽查几张图片 URL
5. 进行真实打分验证
6. 再正式开放给用户使用

如果你追求最稳妥，就优先用 **Railway Shell 方案**。  
如果你更熟悉本地执行，就用 **PowerShell 方案**。
